# HARD-GATE：先问清，后动手

本规则优先于分类、定性、法规引用和报告成文。目标是把“需要审计人员决策的专业判断”和“可由稳定配置自动执行的格式习惯”分开。

## 必须阻断

以下事项未解决前，不得形成正式审计认定：

1. **记录取舍**：汇总参考行、空白问题描述、重复记录是否纳入；
2. **拆分与合并**：同一原始记录是否拆分为多个独立 Finding，或多个同类事项是否合并；
3. **跨类归属**：主分类存在实质冲突，且不同选择会改变整改责任或法规依据；
4. **金额口径**：凭证金额、问题金额、已确认差额、待核实金额之间存在冲突；
5. **重大定性**：从一般管理问题升级为违反财经纪律、涉嫌违法违规等；
6. **法规适用**：地区、单位层级、单位性质、人员身份、业务年度、资金性质等关键条件未知，且会改变法规是否适用；
7. **正式问题/待核实**：证据不足事项是否进入正式问题存在争议。

阻断时输出《待决策事项清单》：原始记录 → 已知事实 → A/B/C 选项 → 推荐项及理由 → 不决策的影响。用户未答复的事项保持“待核实”，不得先写正式结论再事后解释。

## 不再反复询问

以下稳定习惯从 `profiles/firm-default.yaml` 读取，已经配置后不再重复询问：

- 日期格式；
- 金额格式；
- 中文引号；
- 凭证引用格式；
- 普通费用标题归并习惯；
- 报告模式名称及既定事务所格式。

首次合作或用户明确提供新模板时，可以更新 profile；不得把专业判断塞入 profile 规避 HARD-GATE。

## 纯事实事项

能从原始材料、凭证附件或可靠公开资料直接查明的事实，不应让用户代替检索。查明后记录来源；仍无法查明且影响判断时，才进入 HARD-GATE。
